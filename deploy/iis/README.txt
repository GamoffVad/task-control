«Контроль задач» — установка в IIS корпоративной сети (без интернета)
=====================================================================

Что нужно на сервере
  • Windows Server 2016 и новее (x64) — IIS и ASP.NET 4.x включаются установщиком из состава Windows.
  • Локальный SQL Server (проверено на SQL Server 2025). Установщик находит экземпляр сам.
  • Учётная запись, от которой запускается установка: администратор Windows и sysadmin в SQL Server
    (обычно тот, кто устанавливал SQL Server). Иначе укажите -SqlAdminUser/-SqlAdminPassword.
  Ничего скачивать не нужно: Node.js, сервер приложения и драйвер SQL Server — внутри пакета.

Установка и обновление
  1. Скопируйте папку Plan-IIS на сервер (например, в C:\Deploy\Plan-IIS).
  2. Запустите install.bat (права администратора будут запрошены).
  3. Откройте http://10.199.127.27:1500/

  Повторный запуск install.bat из новой версии пакета обновляет приложение. База, данные и
  ключ сеансов сохраняются, пользователям не придётся входить заново.

Что делает установщик
  • Включает компоненты Windows: IIS, ASP.NET 4.x, Windows-аутентификацию IIS.
  • Создаёт базу [Plan] (Cyrillic_General_CI_AS) и таблицы tc_* из db\schema.sql.
  • Копирует сайт в C:\inetpub\wwwroot\Plan, создаёт пул «Plan» и сайт «Plan» на порту 1500.
  • Даёт учётной записи пула «IIS APPPOOL\Plan» доступ к базе по Windows-входу — пароли нигде не хранятся.
  • Открывает TCP 1500 в брандмауэре Windows, запускает сайт и проверяет работу с базой.
  Пустая база заполняется демонстрационными данными; вход администратора: user@example.com / 123456.

Параметры (install.bat -Параметр значение)
  -Port 1500                        порт сайта
  -SitePath C:\inetpub\wwwroot\Plan папка сайта
  -SiteName Plan                    имя сайта и пула IIS
  -SqlServer .\SQLEXPRESS           экземпляр SQL Server (по умолчанию — локальный, самой новой версии)
  -Database Plan                    имя базы
  -SqlAdminUser sa -SqlAdminPassword ...   вход SQL Server для создания базы (если Windows-вход не sysadmin)
  -WindowsAuth auto|on|off          вход через Windows (по умолчанию — если компонент IIS доступен)
  -AdSearch -AdSearchBase "OU=Employees,DC=corp,DC=local"   поиск сотрудников в Active Directory (нужен RSAT)
  -SkipFeatures                     не включать компоненты Windows
  -SkipFirewall                     не создавать правило брандмауэра

Как это устроено
  IIS раздаёт интерфейс (index.html, assets) и через модуль bin\PlanHost.dll проксирует адреса /api/*
  на сервер приложения — App_Data\node\node.exe, который модуль сам запускает на 127.0.0.1
  (порт снаружи недоступен) и перезапускает при сбое. Сервер останавливается вместе с пулом IIS.
  Настройки — appSettings в web.config (ключи «env:ИМЯ» становятся переменными окружения сервера).

Вход через Windows
  Установщик включает Windows-аутентификацию IIS только для адреса /api/windows-login.
  Сам способ входа выбирает администратор приложения: «Администрирование» → «Способ входа».
  Чтобы браузер не спрашивал пароль, добавьте адрес сайта в зону «Местная интрасеть»
  или в политику AuthServerAllowlist (Edge/Chrome). Подробнее — docs/corporate-offline.md.

Если что-то не работает
  • Журнал сервера приложения: C:\inetpub\wwwroot\Plan\App_Data\logs\node-ГГГГММДД.log
  • Ответ http://localhost:1500/api/health на сервере должен содержать "storage":"sqlserver".
  • «Сервер приложения не запустился: Login failed for user 'IIS APPPOOL\Plan'» — запустите install.bat снова
    (он заново выдаст доступ к базе).
  • Компонент Windows не включается без интернета — подключите дистрибутив Windows Server и выполните
    команду, которую покажет установщик (с параметром -Source D:\sources\sxs).
