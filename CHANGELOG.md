# История версий

Формат — [семантическое версионирование](https://semver.org/lang/ru/): MAJOR — смена модели данных, ролей или облика; MINOR — новые возможности; PATCH — исправления.

## 6.2.1 — 09.10.2026

### Изменено
- **Демонстрационный сайт на Vercel снова публикуется, но без базы данных и сервера.** Рабочая версия работает только с SQL Server в корпоративной сети, а до него из интернета не добраться, поэтому Vercel показывает лишь интерфейс с тестовыми данными: приложение собирается в локальном режиме (`VITE_BACKEND=local`), тестовый отдел создаётся в браузере посетителя и хранится в его `localStorage` («данные в этом браузере» в подвале). Данные не общие и не попадают на сервер, вход по форме (`user`, `sidorov` — пароль `123456`), кнопка в шапке возвращает исходные данные. Рабочая публикация в IIS не меняется.
- Возвращены `vercel.json`, `scripts/build-vercel.mjs` (теперь только статика, без функций API) и `scripts/deploy-vercel.mjs`; команды `npm run build:vercel` и `npm run deploy`. Подключение PostgreSQL (Neon) к демо-сайту больше не используется.

### Документация
- README описывает демо-сайт и команды; руководство — команду `npm run build:vercel`. PDF-руководство не пересобиралось.

## 6.2.0 — 09.10.2026

### Добавлено
- **Обнуление показателей** («Администрирование → Оценка → Обнуление показателей»). Баллы складываются из отправленных отчётов, а отчёт — снимок на момент отправки: он не исчезает, когда удаляют задачи, поэтому после очистки тестовых задач начисленные баллы оставались, и сбросить их было нечем. Теперь можно удалить **все отчёты** либо только отчёты недель, начавшихся **раньше выбранной даты**. Над кнопками показано, сколько недель, записей и баллов сейчас в отчётах; кнопка требует второго нажатия («Точно обнулить?»). Задачи, сотрудники, настройки и отметки об исполнении не затрагиваются. Нужно право «Оценка: настраивать правила подсчёта баллов»; на сервере действие `resetScores` проверяется так же.

### Изменено
- **«Показатели» и карточка сотрудника: период начинается с 1-го числа месяца.** Раньше отсчёт шёл со «скользящей» даты (на 9 октября «Месяц» — с 9 сентября). Теперь на 9 октября «Месяц» — с 1 сентября, «Квартал» — с 1 июля, «Полугодие» — с 1 апреля, «Год» — с 1 октября прошлого года; дата начала показана в строке «С даты».

### Документация
- Руководство (глава «Показатели эффективности», вкладка «Оценка») и спецификация описывают новый отсчёт периода и обнуление показателей. PDF-руководство не пересобиралось.

## 6.1.0 — 07.10.2026

### Добавлено
- **Скрипт удаления тестовых данных `scripts/clear-test-data.sql`** — для баз, которые версии до 6.0.0 заполнили демонстрационным отделом. Удаляет демонстрационных сотрудников (почта `@example.com`), задачи `seed-…`, отсутствия `seed-abs-…`, сообщения `m1`–`m4`, записи по демонстрационным задачам в недельных отчётах (отчёт без других записей — целиком), пустые демонстрационные подразделения, а также отсутствия, нормы, сообщения и отметки «прочитано» сотрудников, которых нет в `tc_users`, и временный журнал уведомлений. Настоящие данные, справочники, роли, шаблоны и разделы планирования остаются. По умолчанию скрипт только показывает, сколько записей удалит; удаление — `@apply = 1`; всё в одной транзакции, повторный запуск ничего не находит. Проверен на SQL Server с базой, заполненной как в версии 5.30, и «настоящими» записями поверх неё.
- Скрипт входит в архив для IIS (`scripts\clear-test-data.sql`) и описан в памятке архива, `docs/corporate-offline.md` и `docs/iis-guide.md`.

## 6.0.0 — 07.10.2026

Выпуск меняет способ входа и хранилище, поэтому номер — MAJOR.

### Изменено
- **Вход — только через Windows.** Формы входа, паролей приложения, резервного входа администратора и переключателя «Форма входа / Windows» в «Администрировании → Аутентификация» больше нет. Сотрудник входит доменной учётной записью, которая указана в «Пользователях» (столбец «Windows-логин»); при ошибке на экране входа — причина и кнопка «Войти через Windows». Маршрут `POST /api/login` удалён, действие `saveAuthentication` сервер отклоняет. Сеансы прежнего входа по паролю недействительны: токены подписываются отдельным ключом.
- **Первый администратор — тот, кто публикует.** Если активного администратора в базе нет, администратором становится учётная запись из `TC_ADMIN_LOGIN` в `web.config`; её записывает `deploy-iis.bat` (учётная запись публикующего), даже при `/nosql`. Без `TC_ADMIN_LOGIN` администратор не подставляется (раньше им становилась демонстрационная учётная запись `user` — то есть любой доменный пользователь с таким логином).
- **Тестовых данных нет.** Опубликованное приложение не создаёт и не восстанавливает демонстрационные данные: пустая база получает только справочники, роли, шаблоны, разделы плана и подразделения «ведомство → управление → отдел». Действие `reset` сервер отклоняет, кнопки «Восстановить демонстрационные данные» в шапке нет. Пустая таблица `tc_users` читается как пустой список — демонстрационные сотрудники вместо неё больше не подставляются.
- **Только Microsoft SQL Server.** Хранилище PostgreSQL, файловое хранилище (`data\db.json`), перенос из файла, сборка и публикация на Vercel удалены вместе с пакетами `pg` и PGlite. Без `MSSQL_SERVER` приложение не работает: `/api/health` отвечает 503 (`storage: none`). Сервер разработки работает с локальным SQL Server (база `TaskControlDev`, вход Windows), вход в приложение — учётной записью, под которой он запущен.
- **Схема базы сверяется при каждой публикации.** Таблицы описаны перечнем столбцов (тип, обязательность, значение по умолчанию, ключи, индексы); при каждом запуске недостающие таблицы создаются, недостающие столбцы дописываются — у обязательных со значением по умолчанию для уже существующих строк, — недостающие индексы создаются. Существующие строки и данные не меняются и не удаляются.

### Добавлено
- **Поиск в «Переписке»** — справа от периода: по тексту сообщения и имени автора, без учёта регистра.
- **Колокольчик — общее число событий**, о которых приходят уведомления и которые ждут внимания: просроченные задачи, непрочитанные сообщения коллег и заявки на отсутствие, ожидающие решения. Подсказка показывает разбивку, нажатие открывает раздел с первыми из них.

### Изменено (интерфейс)
- «Тетрис»: фильтр «Виды» — в строке заголовка после «Группы» и перед «Выгрузить в Excel».
- «Переписка»: отступ заголовка от строки разделов, как на остальных страницах.

### Исправлено
- Короткое имя и инициалы сотрудника с ФИО из одного слова (например, администратора `ДОМЕН\логин`) выводились как «ДОМЕН\логин undefined.undefined.».
- `deploy-iis.bat`: копирование больше не зависает на файле, который держит не успевший завершиться `node.exe` (повторы ограничены 5 по 2 с); проверка в конце публикации сообщает о ненастроенном SQL Server, а не о прежнем файловом хранилище; итоговые подсказки описывают вход только через Windows.

### Документация
- Руководство пользователя (раздел «Информация»), спецификация, README, `docs/corporate-offline.md` и `docs/iis-guide.md` описывают вход только через Windows, хранилище SQL Server без тестовых данных и сверку схемы. Снимки экрана входа с формой убраны.
- Скрипты съёмки скриншотов для руководства (`docs/shoot.mjs`, `docs/build-changes.mjs`) рассчитаны на прежний вход по паролю и файловое хранилище и требуют доработки; PDF-руководство не пересобиралось.

## 5.30.0 — 05.10.2026

### Изменено
- **Приложение входит в SQL Server учётной записью Windows, без отдельной учётной записи SQL Server.** `deploy-iis.bat` больше не создаёт `tc_app`: пул приложений `PLAN` работает под учётной записью Windows того, кто публикует (пароль спрашивается один раз на шаге 4, проверяется и хранится IIS в зашифрованном виде; повторная публикация его не спрашивает, после смены пароля — ключ `/password`), и приложение подключается к SQL Server под ней же (`Trusted_Connection`). В `web.config` строки `MSSQL_USER` и `MSSQL_PASSWORD` пустые, пароль SQL Server нигде не хранится. Шаг 7 только создаёт базу, если её нет. Исчезла и ошибка «учётная запись tc_app уже существует, а её пароль в web.config не задан».
- Прежний способ — учётная запись SQL Server `tc_app` с паролем — остаётся по ключу `/sqllogin` (`/resetsql` — новый пароль); заполненный `MSSQL_USER` в `web.config` по-прежнему означает вход учётной записью SQL Server.
- При публикации с другого компьютера (`deploy-iis-remote.bat -AskCredential`) пароль для пула берётся из введённой учётной записи.

### Технически
- Вход Windows — через ODBC: драйвер `msnodesqlv8` (Node-API, подходит для Node.js 18 и новее) лежит в комплекте `dist-iis\node_modules`, на сервере ничего ставить не нужно. Драйвер ODBC выбирается самый новый установленный (`ODBC Driver 18/17 for SQL Server`, `SQL Server Native Client 11.0`, встроенный в Windows `SQL Server`) или задаётся `MSSQL_ODBC_DRIVER`.
- Параметры SQL-запросов переименованы `@p1…` → `@v1…`: имена `@P1…` занимает сам драйвер ODBC.
- Проверки хранилища SQL Server прогнаны на настоящем SQL Server со входом Windows (`npm run test:mssql` без `MSSQL_TEST_USER`).

## 5.28.0 — 05.10.2026

### Добавлено
- **Публикация в IIS одним файлом `deploy-iis.bat`.** Батник сам ставит недостающее: роли Windows Server — IIS, проверку подлинности Windows, консоль IIS и модуль Active Directory для PowerShell (`Install-WindowsFeature`, из состава системы, интернет не нужен); Node.js, URL Rewrite и iisnode — тихо, установщиками `.msi` из новой папки `installers` рядом с батником (в архиве для IIS она есть, список файлов и ссылки — `installers\README.txt`). При первой публикации поиск сотрудников в Active Directory включается сам, если модуль установлен. `deploy-iis-remote.bat` передаёт папку `installers` на сервер и не останавливается на компонентах, которые поставит батник.
- **Перенос данных в SQL Server.** Если приложение успело поработать с файлом `data\db.json` (комплект скопировали вручную, `MSSQL_*` в `web.config` заполнили позже), при первом обращении к пустой базе данные файла переносятся в неё; файл остаётся резервной копией `db.imported-<время>.json`.

### Изменено
- **Способ входа переключается в приложении без правки IIS и `web.config`.** IIS теперь пропускает и анонимные запросы, и запросы с Windows-аутентификацией; учётную запись Windows приложение запрашивает само (ответом `401`) — при входе в режиме «Windows» и по кнопке «Проверить настройку». Поэтому выбор «Форма входа» / «Windows» в **Администрирование → Аутентификация** действует сразу, а проверка показывает доменный логин и в режиме формы.
- **Логин из Active Directory — с доменом:** `ДОМЕН\логин`, как его передаёт IIS при входе через Windows.
- Неверный пароль и недействительный сеанс сервер отдаёт кодом `403` (сеанс — с признаком `relogin`), а не `401`: на `401` IIS запросил бы учётную запись Windows. Токен сеанса передаётся заголовком `X-TC-Token` вместо `Authorization` — этот заголовок нужен IIS; прежний `Authorization: Bearer` сервер по-прежнему принимает.

### Исправлено
- **Доменный пользователь не доходил до приложения.** В `web.config` не было `promoteServerVars`, и iisnode не передавал `X-iisnode-LOGON_USER`; правило URL Rewrite `{LOGON_USER}` срабатывало до проверки подлинности и давало пустой логин. Теперь `promoteServerVars="LOGON_USER,AUTH_USER"` есть в комплекте, `deploy-iis.bat` дописывает его в `web.config` прежних версий, а ненужное правило удаляет.
- **Подмена доменного логина.** Сервер принимал логин из любого заголовка списка (`x-windows-user`, `x-remote-user` и др.), которые браузер может прислать сам, а iisnode не заменяет одноимённый заголовок от браузера, а дописывает свой. Теперь сервер для IIS доверяет только `x-iisnode-logon_user` и берёт его последнее значение; при заданном `WINDOWS_AUTH_HEADER` остальные заголовки не принимаются. В имени заголовка разрешено подчёркивание.
- **Повторная публикация не затирает данные.** Таблицы SQL Server по-прежнему создаются только если их нет, а столбцы добавляются только недостающие. Кроме того, демоданные больше не пишутся в базу, где уже есть строки, а значения по умолчанию не подменяют записанные разделы, даже если в `tc_meta` нет служебных отметок (база восстановлена из копии, создана скриптом `create-database.sql` или перенесена): раньше в таком случае демопользователи с номерами 1–7 перезаписали бы настоящих. `deploy-iis.bat` по-прежнему не трогает `web.config`, папки `data` и `iisnode`.
- **ФИО из Active Directory приходили «кракозябрами»:** PowerShell выводил кириллицу в кодировке консоли (cp866), теперь — в UTF-8.

### Документация
- `docs/corporate-offline.md`, `docs/iis-guide.md`, спецификация и памятка архива описывают публикацию одним батником, папку `installers`, схему входа через Windows и неисправность «в базе SQL Server нет таблиц». PDF-руководство не пересобиралось.
