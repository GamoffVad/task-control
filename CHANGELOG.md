## 5.20.0 — 29.09.2026

### Новое
- **Правила подсчёта баллов настраиваются.** Новая вкладка «Оценка» в «Администрировании» (разрешение «Настраивать правила подсчёта баллов»): кого не учитывать в общей оценке — по подразделению вместе с вложенными или поимённо, — чем делится средний балл и показывать ли разрез по направлениям. Настройки хранятся в базе рядом с настройками входа, отдельной таблицы не требуется.
- **Разрез по направлениям в «Показателях».** Таблица отделений отдела: общий и средний балл, число сотрудников в расчёте и исполненных задач.
- **Исключённые из оценки видны, но не влияют на итог.** Их баллы показываются на своих местах с пометкой «вне оценки», а итог, среднее и лучший результат отдела считаются без них. Над списком появляется строка с числом исключённых, в карточке сотрудника — пояснение.
- Средний балл можно делить на всех сотрудников, только на действующих или только на тех, у кого есть баллы за период; выбранное правило подписано под значением.

### Изменено
- Правила применяются **при показе**: изменение пересчитывает и прошлые периоды. Вес записи отчёта остаётся замороженным на момент отправки — правила меняют только то, как баллы складываются.
- Настройки оценки проверены в PostgreSQL и SQL Server: сохраняются и переживают правки без них.
- Права, добавленные после выпуска базы, дописываются администратору один раз при обновлении. Прежде это делалось отдельным кодом в каждом хранилище — теперь общим помощником, и файловое хранилище тоже охвачено.

## 5.16.0 — 28.09.2026

### Новое
- **Учётная запись SQL Server и база создаются при публикации.** Шаг 7 файла `deploy-iis.bat` заводит учётную запись приложения со случайным паролем, создаёт базу, делает учётную запись её владельцем и сам вписывает `MSSQL_SERVER`, `MSSQL_DATABASE`, `MSSQL_USER`, `MSSQL_PASSWORD` и `AUTH_SECRET` в `web.config`. Ручная подготовка SQL Server больше не нужна: после одного запуска публикации приложение открывается с работающей базой. Таблицы, как и раньше, создаёт само приложение при первом обращении.
- Отдельный скрипт `scripts/setup-sql.ps1` (он же кладётся рядом с сервером в комплекте IIS) выполняет только этот шаг — если SQL Server подняли позже публикации. Повторный запуск безопасен: существующие учётную запись, базу и пароль он не трогает; ключ `-Reset` задаёт новый пароль, если прежний потерян.
- Ключи публикации: `/nosql` — не трогать SQL Server, `/resetsql` — задать учётной записи новый пароль.

### Изменено
- Серверная роль `dbcreator` приложению больше не нужна: базу создаёт скрипт настройки и делает учётную запись её владельцем. Роль требуется, только если базу не создавать заранее и позволить приложению создать её самому.

### Документация
- Разделы о SQL Server в `docs/corporate-offline.md` и в руководстве переписаны под автоматическую настройку; ручной способ оставлен на случай, когда политика запрещает автоматику. PDF-руководство пересобрано.

## 5.15.0 — 28.09.2026

### Новое
- **Хранилище в Microsoft SQL Server.** В корпоративной сети приложение работает с локальным SQL Server (2016 и новее, проверено на 2025): **база и таблицы создаются сами при первом обращении**, разворачивать схему вручную не нужно. Настройки — `MSSQL_SERVER`, `MSSQL_DATABASE`, `MSSQL_USER`, `MSSQL_PASSWORD`, при необходимости `MSSQL_INSTANCE`, `MSSQL_PORT`, `MSSQL_DOMAIN`, `MSSQL_ENCRYPT`; в публикации IIS они задаются в разделе `appSettings` файла `web.config`. Хранилище выбирается по настройкам: SQL Server, иначе PostgreSQL, иначе файл рядом с сервером; `GET /api/health` показывает выбранное. Драйвер — `mssql` на чистом JavaScript, поэтому комплект IIS остаётся одним файлом без нативных модулей.
- Создаются 14 таблиц с префиксом `tc_`. Изменения пишутся в транзакции под общей блокировкой `sp_getapplock`: одновременные правки разных сотрудников не теряются, при ошибке транзакция откатывается целиком, записываются только добавленные, изменённые и удалённые строки. Повторный запуск схемы ничего не ломает, новые столбцы дописываются к существующим таблицам.
- Ключ подписи сеансов без `AUTH_SECRET` выводится из настроек SQL Server, а не остаётся отладочным.
- `npm run test:mssql` — 11 тестов хранилища на настоящем SQL Server: создание базы и таблиц, чтение без искажений, даты без сдвига часового пояса, частичная запись, откат транзакции, одновременные правки, перенос базы прежней версии.

### Изменено
- **Публикация в IIS выверена.** `deploy-iis.bat` теперь действительно проверяет наличие iisnode и URL Rewrite — ищет их в списке модулей IIS, потому что прежняя проверка проходила и без установленных модулей. При первой публикации в `web.config` записывается найденный путь к `node.exe` (иначе iisnode ищет его только в `Program Files`), создаётся папка `iisnode` для журналов с правом записи, а правило брандмауэра получило имя латиницей.

### Исправлено
- Параметр `esbuild.target` в настройках сборки игнорировался: Vite 8 перешёл на oxc и предупреждал об этом при каждом запуске. Цель `chrome109` задана параметром `oxc`.
- **Список последнего фильтра в строке** (например, «Категории» в «Календаре») раскрывался вправо и обрезался краем окна — названия категорий были не видны. Теперь у последнего фильтра список раскрывается влево.
- Скрипт съёмки документации искал переключатель категорий «Календаря» по прежней разметке и падал, оставляя папку скриншотов пустой.

### Документация
- PDF-руководство пересобрано. В главе «Для администратора» появился раздел «Публикация в IIS» с пошаговым порядком: подготовка сервера, перенос проекта, запуск батника, настройки `appSettings`, проверка Windows-входа и повторная публикация.
- `docs/corporate-offline.md`: новый раздел о хранилище в SQL Server — учётная запись, права, настройки, что создаётся и как проверить; раздел о публикации расписан по шагам — что именно делает батник и что сохраняется при повторном запуске.

## 5.14.0 — 28.09.2026

### Новое
- **Выгрузка «Тетриса» в Excel.** Кнопка «Выгрузить в Excel» сохраняет матрицу месяца файлом `tetris-ГГГГ-ММ.xlsx`: строки — сотрудники, столбцы — дни, заливка ячейки — вид события. Цвета берутся из тех же «Словарей», что и полосы на графике, поэтому совпадают с ним: насыщенный тон — согласовано, светлее — заявка. Сохраняются отметки сроков (`•` назначен, `✓` исполнено, `!` срок во время события), остатки отпуска и отгулов, строка «Отсутствуют, %», легенда и список событий месяца. Шапка и первые две колонки закреплены; учитываются фильтр видов и выбранная группа. Книга собирается в браузере без внешних библиотек.
- **Публикация в IIS.** Файл `deploy-iis.bat` от имени администратора собирает комплект, копирует его в `C:\inetpub\wwwroot\PLAN`, создаёт сайт `http://10.199.127.27:1500` и отдельный пул приложений, включает Windows-аутентификацию с `Negotiate` выше `NTLM`, добавляет правило передачи доменного логина и открывает порт в брандмауэре. Комплект собирается и отдельно — `npm run build:iis` кладёт в `dist-iis` сервер `server.cjs`, интерфейс и `web.config`. При повторной публикации настройки и данные сохраняются.
- **Проверка Windows-входа.** В «Администрировании» → «Аутентификация» появился блок с кнопкой «Проверить настройку»: показывает, что сервер увидел в запросе — включено ли доверие прокси, совпал ли секрет, какие заголовки пришли, какой доменный логин взят и с каким сотрудником сопоставлен. При ошибке называется конкретная причина. Новый адрес `GET /api/windows-check` доступен с правом «Управление способом входа».

### Исправлено
- **Переключатель Windows-аутентификации в корпоративной публикации.** Режим больше не откатывался к форме при перезапуске сервера, а сам переключатель доступен всегда. Доменный логин принимается в заголовках IIS, iisnode, ARR и nginx (`x-windows-user`, `x-iisnode-logon_user`, `x-iisnode-auth_user`, `x-iis-user`, `x-remote-user`, `x-forwarded-user`, `remote-user`, `auth-user`); свой заголовок задаётся переменной `WINDOWS_AUTH_HEADER`, общий секрет прокси — `WINDOWS_AUTH_PROXY_SECRET`. Логин сопоставляется в трёх формах: `DOMAIN\ivanov`, `ivanov@corp.local`, `ivanov`. Форма входа блокируется, только когда сервер действительно видит доменного пользователя в самом запросе, поэтому неверная настройка прокси больше не запирает сотрудников снаружи.
- **Цвет ячейки в выгрузке Excel.** Ячейка без текста не попадала в файл вместе со своим оформлением, поэтому день события без отметки задачи оставался незакрашенным.

### Изменено
- **Совместимость с Google Chrome 109** — последней версией для Windows 7. Функция `color-mix()` убрана из стилей: прозрачность цветов считается через `rgb(var(--токен-rgb) / доля)`, в обе темы добавлены каналы цветов. Цель сборки — `chrome109`.
- **Полное редактирование сотрудников.** В «Администрировании» окно «Редактировать сотрудника» меняет любые данные, включая ФИО, независимо от способа входа и настройки Active Directory; «Добавить сотрудника» позволяет завести учётную запись вручную, а каталог остаётся необязательной подсказкой. Проверяются непустые ФИО и должность и неповторяющаяся почта.

### Документация
- `docs/corporate-offline.md`: пошаговая настройка IIS с примером правила URL Rewrite, список принимаемых заголовков, переменные окружения, групповая политика браузера, сопоставление сотрудников и проверка настройки; раздел о публикации файлом `deploy-iis.bat`.
- Руководство: в главе «Тетрис» — выгрузка в Excel, в главе «Администрирование» — полное редактирование сотрудников и проверка Windows-входа, в главе «Для администратора» — публикация в IIS.
