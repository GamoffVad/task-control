# Публикация «Контроля задач» в IIS корпоративной сети

Инструкция для администратора. Сервер работает **без интернета**: ничего не скачивается и не собирается на нём. Всё нужное готовится заранее на компьютере с интернетом и привозится на носителе. Опубликованное приложение работает по адресу `http://10.199.127.27:1500/` (меняется в `deploy-iis.bat`), хранит данные в Microsoft SQL Server и пускает сотрудников по Windows-учётной записи.

---

## 1. Схема и что понадобится

Браузер сотрудника → IIS (Windows-аутентификация) → Node.js внутри IIS (модуль iisnode) → Microsoft SQL Server.

| Что | Где берётся | Зачем |
|---|---|---|
| Архив `task-control-iis-<версия>.zip` | выпуск проекта на GitHub или `npm run pack:iis` на компьютере с интернетом | готовый комплект: сервер приложения, интерфейс, `deploy-iis.bat`, скрипты, инструкция |
| Node.js 18 или новее (`.msi`) | https://nodejs.org | запускает сервер приложения |
| iisnode (`.msi`) | https://github.com/Azure/iisnode/releases | модуль IIS для Node.js |
| URL Rewrite (`.msi`) | https://www.iis.net/downloads/microsoft/url-rewrite | модуль IIS для правил адресов |
| Роль «Веб-сервер IIS» | компоненты Windows, интернет не нужен | сам IIS |
| Microsoft SQL Server 2016 и новее | уже есть в сети | хранилище; смешанный режим проверки подлинности |

Папки `dist-iis` в репозитории нет: это результат сборки, поэтому исходников на сервере недостаточно. Нужен именно архив.

**Права:** администратор на сервере IIS; для автоматической настройки базы — `sysadmin` (или `dbcreator` и `securityadmin`) в SQL Server.

---

## 2. Подготовка (один раз)

1. На компьютере с интернетом скачайте архив `task-control-iis-<версия>.zip` из раздела Releases проекта. Либо соберите его сами: в папке проекта `npm install`, затем `npm run pack:iis` — архив появится в `release\`.
2. Скачайте установщики Node.js, iisnode и URL Rewrite и положите их в папку `installers` архива (список — `installers\README.txt`). Ставить их вручную не нужно: `deploy-iis.bat` установит то, чего нет на сервере.
3. Перенесите всё на сервер (или на компьютер, с которого будете публиковать) на съёмном носителе.
4. Распакуйте архив в любую папку. В нём лежат `deploy-iis.bat`, `deploy-iis-remote.bat`, папки `dist-iis`, `installers`, `scripts` и эта инструкция. Роль «Веб-сервер IIS», проверку подлинности Windows и модуль Active Directory батник включит сам — они входят в Windows Server, интернет не нужен.

## 3. Публикация на самом сервере

1. Откройте `deploy-iis.bat` в Блокноте и проверьте первые строки: `IP` и `PORT` (адрес и порт сайта), `TARGET` (папка, по умолчанию `C:\inetpub\wwwroot\PLAN`), `SQLSERVER` (имя сервера SQL: `СЕРВЕР` или `СЕРВЕР\ЭКЗЕМПЛЯР`).
2. Запустите `deploy-iis.bat` **от имени администратора** (правая кнопка → «Запуск от имени администратора»).
3. Дождитесь сообщения «Готово. Установлена версия …».

Если рядом нет исходников проекта, батник сам берёт готовую папку `dist-iis`; ключ `/nobuild` указывать не нужно.

**Что делает батник:**

1. Проверяет права администратора и ставит недостающее: роли Windows Server — из состава системы, Node.js, URL Rewrite и iisnode — из папки `installers`. Если установщика нет, останавливается и называет нужный файл.
2. Показывает версию комплекта и версию, которая стоит на сервере.
3. Останавливает пул, копирует файлы в папку сайта. `web.config`, папки `data` и `iisnode` не перезаписываются: настройки, данные и журналы сохраняются.
4. Выдаёт права на папку учётным записям `IIS_IUSRS` и пула приложений.
5. Создаёт пул приложений `PLAN` (без управляемого кода, запускается всегда, без простоя и перезапусков по расписанию).
6. Создаёт сайт `PLAN` с привязкой к адресу и порту.
7. Включает проверку подлинности Windows вместе с анонимной, выключает обычную, ставит `Negotiate` выше `NTLM`. Вход в приложение — только по учётной записи Windows: формы и паролей приложения нет. Проверка настройки — **Администрирование → Аутентификация**.
8. Настраивает SQL Server: создаёт базу `TaskControl`, если её нет, и записывает в `web.config` вход Windows (без учётной записи SQL Server и пароля) и ключ подписи сеансов. Пул `PLAN` работает под учётной записью Windows того, кто публикует: пароль батник спрашивает один раз (на шаге 4) и проверяет. После запуска сайта обращается к приложению: оно сверяет схему базы — создаёт недостающие таблицы, столбцы и индексы, не трогая данные. Тестовых данных нет: в пустой базе — справочники, роли, шаблоны и разделы плана, администратор — публикующий (`TC_ADMIN_LOGIN`). Батник сообщает, что база готова и приложение работает с SQL Server.
9. Открывает порт в брандмауэре, запускает пул и сайт и проверяет, что на сервере теперь версия комплекта.

**Ключи батника:** `/nosql` — не трогать SQL Server (базу создали вручную); `/password` — спросить пароль Windows заново (после его смены); `/sqllogin` — прежний способ с учётной записью SQL Server `tc_app` (`/resetsql` — задать ей новый пароль); `/nobuild` — не собирать (нужен только при наличии исходников).

## 4. Публикация с другого компьютера сети

Можно публиковать с любого компьютера сети, ничего не запуская на сервере: комплект передаётся по PowerShell Remoting (WinRM), и на сервере выполняется тот же `deploy-iis.bat`.

```bat
deploy-iis-remote.bat -Server SRV-IIS
```

**Что нужно:** права администратора на сервере (ваша учётная запись или другая: `-AskCredential`); на сервере включён WinRM (в Windows Server включён по умолчанию, иначе один раз `Enable-PSRemoting -Force`); открыт порт 5985.

**Сначала проверьте сервер** — ключ `-Check` ничего не меняет и показывает, чего не хватает:

```bat
deploy-iis-remote.bat -Server SRV-IIS -Check
```

Скрипт выводит права, роль IIS, iisnode, URL Rewrite, версию Node.js и версию приложения на сервере.

| Параметр | Назначение |
|---|---|
| `-Server ИМЯ` | имя или адрес сервера IIS |
| `-Check` | только проверить сервер |
| `-AskCredential` | войти другой учётной записью |
| `-NoSql`, `-ResetSql` | как `/nosql` и `/resetsql` |
| `-Ip`, `-Port`, `-Site`, `-Pool`, `-Target` | адрес, порт, имя сайта и пула, папка, если отличаются от значений в `deploy-iis.bat` |
| `-SqlServer`, `-SqlDb`, `-SqlLogin` | сервер, база и учётная запись SQL Server |

Пример: `deploy-iis-remote.bat -Server SRV-IIS -Ip 10.199.127.27 -Port 1500 -NoSql`. Вывод публикации сохраняется в `deploy-remote-<сервер>.log` рядом со скриптом.

**Если подключиться не удалось:** проверьте, что сервер включён и порт 5985 доступен, что на нём включён WinRM и что у вас есть права администратора. Для сервера вне домена или при указании адреса вместо имени добавьте его в доверенные на своём компьютере: `Set-Item WSMan:\localhost\Client\TrustedHosts -Value "СЕРВЕР"`.

## 5. База данных

**Автоматически (по умолчанию).** Шаг 8 батника сам создаёт базу `TaskControl`, а таблицы приложение создаёт сразу после публикации. Приложение входит в SQL Server учётной записью Windows пула — того, кто публикует; учётная запись SQL Server не нужна. Подходит, когда SQL Server стоит на том же сервере, что и IIS.

**Вручную.** Если базу удобнее подготовить самому или SQL Server стоит на отдельном компьютере (учётные данные с сервера IIS дальше, на третий компьютер, не передаются):

1. Откройте `scripts\create-database.sql` в SQL Server Management Studio под учётной записью с правами `sysadmin`.
2. В разделе 2 замените `ЗАМЕНИТЕ_НА_СВОЙ_ПАРОЛЬ` на пароль учётной записи `tc_app`. Пока пароль не заменён, учётная запись не создаётся.
3. Выполните скрипт целиком (F5). Он создаёт базу, учётную запись с правами владельца базы и 14 таблиц с индексами; повторный запуск безопасен. Из командной строки: `sqlcmd -S СЕРВЕР -E -C -b -i create-database.sql`.
4. В разделе `appSettings` файла `web.config` (`C:\inetpub\wwwroot\PLAN\web.config`) задайте: `MSSQL_SERVER` (имя сервера или `СЕРВЕР\ЭКЗЕМПЛЯР`), `MSSQL_DATABASE` (`TaskControl`), `MSSQL_USER` (`tc_app`), `MSSQL_PASSWORD` и `AUTH_SECRET` (любая длинная случайная строка).
5. Публикуйте с ключом `/nosql`: `deploy-iis.bat /nosql` или `deploy-iis-remote.bat -Server СЕРВЕР -NoSql`.

Таблицы создаются пустыми; приложение записывает только справочники и роли, тестовых данных нет. Администратор — публикующий (`TC_ADMIN_LOGIN` в `web.config`; его записывает `deploy-iis.bat` даже с ключом `/nosql`), остальные сотрудники вносятся в «Администрировании».

**Обнуление баллов.** Баллы берутся из отправленных отчётов и не исчезают, когда задачи удаляют. Чтобы сбросить показатели после очистки тестовых данных, откройте «Администрирование → Оценка → Обнуление показателей»: можно удалить все отчёты либо отчёты недель до выбранной даты (задачи и сотрудники не затрагиваются, действие нельзя отменить).

**Удаление тестовых данных, оставшихся от версий до 6.0.0.** Скрипт `scripts\clear-test-data.sql`: сделайте резервную копию базы, откройте скрипт в SQL Server Management Studio на базе `TaskControl` и выполните — он только покажет, сколько записей удалит. Затем замените в строке `declare @apply bit = 0` ноль на `1` и выполните ещё раз. Удаляются демонстрационные сотрудники (`@example.com`), их задачи, отсутствия, сообщения, нормы, записи в отчётах и пустые демонстрационные подразделения; настоящие данные, справочники, роли, шаблоны и разделы планирования остаются. Всё — в одной транзакции.

## 6. Проверка и первый вход

1. Откройте `http://<адрес>:<порт>/api/health`. Должно быть `{"ok":true,"storage":"sqlserver"}`. Код 503 — база не настроена или недоступна (причина — в журнале `iisnode`, см. раздел 8).
2. Откройте `http://<адрес>:<порт>/` с рабочего компьютера: приложение открывается сразу, без формы — вы входите своей доменной учётной записью Windows. **Первым администратором становится тот, кто публиковал** (его учётная запись записана в `web.config` как `TC_ADMIN_LOGIN`, пока в базе нет другого администратора). Внизу страницы указана версия — она должна совпадать с версией комплекта.
3. Перейдите в «Администрирование → Аутентификация» и нажмите «Проверить настройку»: видно, какой доменный логин получил сервер и с каким сотрудником он сопоставлен.
4. В «Администрирование → Пользователи» добавьте сотрудников (можно поиском в Active Directory) и заполните **Windows-логин** каждого (форма `DOMAIN\ivanov`, `ivanov@corp.local` или просто `ivanov`): по нему приложение узнаёт сотрудника. Сотрудник, чей логин не внесён или чья запись отключена, в приложение не войдёт.
5. Назначьте роли и подразделения («Администрирование → Пользователи, Подразделения, Роли и разрешения»).

Если сотрудника приложение не узнало, сервер отвечает, что учётная запись Windows не сопоставлена с активным пользователем: проверьте Windows-логин в его карточке.

**Групповая политика браузеров.** Чтобы Chrome и Edge отправляли учётные данные Windows без запроса, добавьте адрес приложения в `AuthServerAllowlist` (политика Chrome/Edge), а при делегировании — в `AuthNegotiateDelegateAllowlist`.

## 7. Обновление

1. На компьютере с интернетом скачайте новый архив из Releases и перенесите его на носитель.
2. Распакуйте и снова запустите `deploy-iis.bat` (или `deploy-iis-remote.bat -Server ...`).
3. Убедитесь, что в начале вывода «Версия комплекта» — новая, а в конце «Установлена версия» совпадает с ней. Если не совпала, батник сообщает, что файлы не обновились.
4. Нажмите в браузере Ctrl+F5, чтобы сбросить кэш страницы.

`web.config`, `data` и журналы не затрагиваются, поэтому настройки, пароль базы и сеансы сохраняются.

## 8. Если что-то не работает

| Симптом | Что проверить |
|---|---|
| Батник пишет «не найден готовый комплект dist-iis» | Запускаете из папки с исходниками без сборки. Нужен архив `task-control-iis-<версия>.zip` и запуск из его распакованной папки. |
| «запустите файл от имени администратора» | Правая кнопка по `deploy-iis.bat` → «Запуск от имени администратора». |
| «не установлен модуль iisnode / URL Rewrite» | Установите модуль установщиком `.msi` и повторите запуск. |
| После публикации старая версия | Сравните «На сервере сейчас» и «Установлена версия» в выводе батника; запустите батник и `dist-iis` из архива новой версии; Ctrl+F5 в браузере. |
| Страница не открывается, 500 | Последний файл в `C:\inetpub\wwwroot\PLAN\iisnode\` — вывод Node.js с причиной; журнал Windows «Приложение». |
| `/api/health`: 503, `storage: none` | Не заполнены `MSSQL_*` в `web.config` (комплект скопирован вручную или публикация шла с `/nosql`). Других хранилищ, кроме SQL Server, нет. Запустите `deploy-iis.bat` или только шаг базы: `powershell -ExecutionPolicy Bypass -File C:\inetpub\wwwroot\PLAN\setup-sql.ps1 -Server localhost -ConfigPath C:\inetpub\wwwroot\PLAN\web.config`. |
| `/api/health`: 503 | SQL Server недоступен или неверный пароль: проверьте `MSSQL_SERVER`, `MSSQL_USER`, `MSSQL_PASSWORD`, порт 1433 и смешанный режим проверки подлинности. |
| Сотрудник не может войти через Windows | «Администрирование → Аутентификация → Проверить настройку»: виден ли логин и сопоставлен ли он; заполнен ли Windows-логин сотрудника; включена ли политика `AuthServerAllowlist`. |
| Не создаётся база SQL Server | У запускающего нет прав `sysadmin` (или `dbcreator`): создайте базу вручную (раздел 5) и публикуйте с `/nosql`. |

Вывод батника удобно сохранить в файл: `deploy-iis.bat > deploy-log.txt 2>&1` (в командной строке от имени администратора).

## 9. Справка: настройки и каталоги

**Каталоги на сервере:** `C:\inetpub\wwwroot\PLAN` — приложение; `web.config` — настройки; `iisnode\` — журналы Node.js; `version.txt` — версия установленного комплекта.

**Настройки в `web.config` (раздел `appSettings`):**

| Параметр | Назначение |
|---|---|
| `MSSQL_SERVER`, `MSSQL_DATABASE`, `MSSQL_USER`, `MSSQL_PASSWORD` | подключение к SQL Server; заполняются батником или вручную |
| `TC_ADMIN_LOGIN` | учётная запись Windows публикующего (`ДОМЕН\логин`): администратор, пока в базе нет другого; записывает `deploy-iis.bat` |
| `AUTH_SECRET` | ключ подписи сеансов; если сменить, все сотрудники войдут заново |
| `WINDOWS_AUTH_TRUST_PROXY` | `true` — приложение принимает доменного пользователя от IIS (по умолчанию включено в комплекте) |
| `WINDOWS_AUTH_PROXY_SECRET` | необязательный общий секрет прокси |
| `AD_SEARCH_ENABLED`, `AD_SEARCH_BASE` | необязательный поиск сотрудников в Active Directory при их добавлении |

После сохранения `web.config` IIS перезапускает приложение сам.

**Безопасность:** порт Node.js не публикуйте для рабочих станций — запросы должны идти только через IIS; `AUTH_SECRET` не передавайте открытым текстом; пароль Windows для пула IIS хранит сам в зашифрованном виде; вход в приложение — только через Windows, паролей приложения нет.
